Это техническое задание (ТЗ) описывает финальную версию системы RentMyBike для продакшн-среды. Система представляет собой P2P-маркетплейс для аренды транспорта (фокус на электробайки VinFast) в Нячанге, Вьетнам.
Техническое задание: Система RentMyBike (Production Ready)
1. Обзор системы
RentMyBike — это высокотехнологичная платформа, объединяющая владельцев транспорта и арендаторов. Система интегрирует ИИ для автоматизации рутинных процессов (проверка документов, распознавание техники) и использует Telegram как основной канал взаимодействия.
2. Архитектура и Стек
Frontend: React 18 + TypeScript + Tailwind CSS + Framer Motion.
Backend: Node.js (Express) + tsx.
База данных: SQLite (локальное хранилище для скорости) + Supabase (Auth & Remote Sync).
Интеграции:
Google Gemini AI: Анализ KYC, генерация фото, распознавание моделей.
Telegram Bot API: Уведомления, вход через Mini App.
Resend: Транзакционные Email-уведомления.
Supabase Storage: Хранение оригиналов документов и фото.
3. Ролевая модель и Лимиты
Гость: Просмотр маркетплейса, поиск.
Пользователь (Free):
Лимит: 1 активное объявление.
Базовая верификация.
Бизнес (Paid):
Безлимитные объявления.
Приоритет в поисковой выдаче.
Расширенная аналитика доходов.
Значок "Verified Business".
Админ: Полное управление системой, модерация, финансовый мониторинг.
4. Ключевые функции (Features)
4.1. Смарт-Маркетплейс
Фильтрация: По типу (байк/авто), двигателю (электро/бензин), цене и локации.
AI-Поиск: Возможность искать фразами (например, "быстрый байк для двоих").
Карточка товара: Интерактивная галерея, статус доступности в реальном времени.
4.2. Система управления листингом (Listing 2.0)
AI Photo Gen: Если у владельца нет фото, ИИ генерирует студийное изображение модели.
AI Recognition: Автозаполнение характеристик (марка, модель, объем) по одной фотографии.
Динамическое ценообразование: Установка скидок за неделю/месяц аренды.
4.3. AI-Верификация (KYC)
Автоматическое сравнение селфи с фото в паспорте/правах через Gemini Pro Vision.
Проверка срока действия документа и категории прав (A1/A2 для Вьетнама).
Мгновенный вердикт: "Verified", "Rejected" или "Manual Review".
5. Главная проверка: Оплата и Подписка (Business Plan)
Это критический узел системы, обеспечивающий монетизацию.
5.1. Процесс апгрейда
Пользователь нажимает "Upgrade to Business" в дашборде.
Система генерирует уникальный инвойс (QR-код для перевода или ссылка на Stripe/Crypto).
Механизм проверки:
Ручной (MVP): Пользователь загружает скриншот чека -> Админ получает уведомление -> Проверяет транзакцию в банке -> Нажимает "Approve" в Admin Panel.
Автоматический (Scale): Webhook от платежного шлюза -> API сервер меняет subscription_status на business в БД и метаданных Supabase.
5.2. Логика блокировки фич
При попытке добавить 2-й байк, сервер делает запрос:
code
SQL
SELECT COUNT(*) FROM vehicles WHERE owner_id = ? AND status != 'deleted'
Если count >= 1 AND subscription_status != 'business', фронтенд блокирует форму и показывает модальное окно оплаты.
Проверка на бэкенде: API /api/vehicles (POST) жестко валидирует лимит перед записью в БД.
6. Интеграция с Telegram
Вход: Авторизация через Telegram WebApp (одним кликом).
Уведомления:
Владельцу: "У вас новый запрос на бронирование от @user".
Арендатору: "Ваша заявка подтверждена. Контакт владельца: +84...".
Бот-ассистент: Ответы на вопросы о правилах парковки и штрафах в Нячанге.
7. Админ-панель (Control Center)
Очередь модерации: Проверка новых байков перед публикацией.
Финансовый дашборд: Общая выручка, количество платных подписок, конверсия.
Impersonation: Возможность зайти под любым пользователем для решения проблем (только для SuperAdmin).
8. Безопасность и Production-требования
HTTPS: Обязательно для всех API вызовов.
Rate Limiting: Защита от перебора API и спама уведомлениями.
CORS: Строгое ограничение доменов, имеющих доступ к API.
Environment Variables: Все ключи (Gemini, Supabase, Resend) хранятся в защищенных переменных окружения, никогда не попадая в клиентский код.
